## Intent

**Problem:** The `sanjit-portfolio` repo has no Next.js code yet. The architecture spine pins Next.js 16.3.6+, React 19.2, TypeScript ≥ 5.1, Tailwind CSS v4 (CSS-first, no `tailwind.config.ts`), Zod 4.6+, `@next/mdx` v3, and pnpm with a committed `pnpm-lock.yaml`. Without a green scaffold, every downstream epic (E2–E5) cannot compile against the closed lists in AD-13/15/17/18/19/20.

**Approach:** Initialize the project manually so every pinned dependency, scripts entry, and toolchain rule is present from the first commit. No `create-next-app` (we do not control whether it pulls Tailwind config files; AD-18 forbids `tailwind.config.ts`). CI uses `--frozen-lockfile` on Vercel; the lockfile is committed from day 1.

### 2026-09-24-1 — `@next/mdx` pin changed from `^3` to `^16.3.6`

- **Triggered by:** step-03 implementation report — `@next/mdx` `^3` could not be resolved against the npm registry (no v3 line is published; the package tracks the Next major in v16).
- **Amended:** Task list entry for `package.json` — pin is now `@next/mdx@^16.3.6` (was `@next/mdx@^3`).
- **Known-bad state avoided:** A future re-derivation that re-installed from the literal spec would fail dependency resolution at `pnpm install`, blocking Vercel deploy on day 1.
- **KEEP:** `pnpm-lock.yaml` already pins the correct lineage; do not regenerate. The MDX 3.x feature surface is preserved through `@next/mdx@^16.3.6`'s bundled `mdx` packages.

### 2026-09-24-2 — `eslint.config.mjs` flat-config shape; `pnpm lint` uses `eslint .`, not `next lint`

- **Triggered by:** step-03 implementation report — Next 16.3.6 removed the `next lint` wrapper, and the legacy `FlatCompat` shim from `eslint-config-next` errors with "circular structure to JSON" when imported.
- **Amended:** Task list entry for `eslint.config.mjs` (specifies the supported flat-config spreading path) and `package.json` scripts (notes `lint` runs `eslint .`).
- **Known-bad state avoided:** Re-derivation that runs `next lint` would exit non-zero on a missing binary; re-derivation that uses `FlatCompat` would fail to load the config.
- **KEEP:** AC #5 (`pnpm lint` exits 0 with zero errors) is the binding contract; the underlying invocation is an implementation detail. Do not regress to `next lint`.

### 2026-09-24-3 — `tsconfig.json` `jsx` is `react-jsx`, not `preserve`

- **Triggered by:** step-03 implementation report — Next 16's `next build` rewrites the spec's `jsx: "preserve"` to `jsx: "react-jsx"` for App Router projects; persisting `"preserve"` breaks the build.
- **Amended:** Task list entry for `tsconfig.json` — `jsx` is now `"react-jsx"`. AC #4 (typecheck exit 0) is unchanged in meaning.
- **Known-bad state avoided:** Re-derivation that writes `jsx: "preserve"` would compile but fail at runtime when JSX is emitted as raw function calls instead of transformed.
- **KEEP:** `tsc --noEmit` must continue to exit 0 against the pinned TS version; do not relax `strict` or `noUncheckedIndexedAccess`.

### 2026-09-24-4 — `vercel.json` sets `installCommand` and `buildCommand` explicitly

- **Triggered by:** step-04 review (Blind Hunter + Edge Case Hunter) — Vercel's default `installCommand` is `npm install`, not pnpm; without an override the first Vercel deploy would bypass `pnpm-lock.yaml` and invalidate AC #1's CI contract.
- **Amended:** Task list entry for `vercel.json` — file now sets `"installCommand": "pnpm install --frozen-lockfile"` and `"buildCommand": "pnpm build"` alongside `framework: "nextjs"`.
- **Known-bad state avoided:** First Vercel deploy would otherwise run `npm install`, regenerate the lockfile semantics, and silently break dependency reproducibility.
- **KEEP:** If a later story changes the install or build command, document the spine reason in the next amendment and update this log entry.

### 2026-09-24-5 — `tsconfig.json` adds `baseUrl: "."`

- **Triggered by:** step-04 review (Edge Case Hunter) — TS 5.x `paths` with `moduleResolution: "bundler"` resolves from the file directory when `baseUrl` is unset, but some IDE tooling and editor scenarios lose `@/*` mapping reliability without an explicit `baseUrl`.
- **Amended:** Task list entry for `tsconfig.json` — `baseUrl: "."` added.
- **Known-bad state avoided:** Future re-derivation that omits `baseUrl` could leave `@/*` imports unresolvable in non-`tsc` tooling (Vercel build is fine; CI linting via `@typescript-eslint` may complain).
- **KEEP:** Path alias `@/*` → `./*` must continue to resolve via Next's bundler during build.

### 2026-09-24-6 — `eslint.config.mjs` adds explicit `ignores`

- **Triggered by:** step-04 review (Blind Hunter) — spreading `eslint-config-next/core-web-vitals` + `eslint-config-next/typescript` inherits the next-core default ignores, but those may not include `coverage/**` and `*.tsbuildinfo` for projects that later adopt Vitest / `--incremental`.
- **Amended:** Task list entry for `eslint.config.mjs` — added `ignores: [".next/**", "node_modules/**", "*.tsbuildinfo", "coverage/**"]`.
- **Known-bad state avoided:** Future re-derivation in a downstream epic that introduces Vitest may produce noisy lint errors on coverage output files.
- **KEEP:** AC #5 (`pnpm lint` exits 0 with zero errors). Do not remove this entry; if you need to ignore additional paths, append them.

### 2026-09-24-7 — `package.json` drops the unused `@eslint/eslintrc` devDep

- **Triggered by:** step-04 review (Blind Hunter + Edge Case Hunter) — Next 16's native flat-config exports (`eslint-config-next/core-web-vitals` + `eslint-config-next/typescript`) do not require the legacy `@eslint/eslintrc` shim.
- **Amended:** Task list entry for `package.json` — `@eslint/eslintrc@^3` removed. Lockfile regenerated.
- **Known-bad state avoided:** Carrying unused devDependencies inflates install time and confuses downstream refactors that touch ESLint.
- **KEEP:** If a later story migrates to legacy ESLint configs, add the dep back and log the change here.

## Design Notes

- **Why `eslint.config.mjs` (flat config) and not legacy `.eslintrc.json`:** Next 16 emits flat-config ESLint by default; legacy `.eslintrc` requires an opt-in. Matching the default keeps the lint script trivial (`eslint .`).
- **Why `next.config.mjs` instead of `next.config.js`:** ESM-only module file matches the rest of the modern toolchain; avoids CJS/ESM interop surprises on Vercel.
- **Why the placeholder `<h1>` is `sanjit.dev` (lowercase, no dot in a fragment):** Vercel preview URLs use the project slug, not the deploy URL; keeping the homepage text intentionally minimal lets E1.4's route-invariant CI assert real content shipped in E1.11 without false positives today.
- **Why no `prettier`, `husky`, or `commitlint` in this story:** Out of spine scope. AGENTS.md conventions list formatting only, and adding formatters requires user approval ("Ask First").
