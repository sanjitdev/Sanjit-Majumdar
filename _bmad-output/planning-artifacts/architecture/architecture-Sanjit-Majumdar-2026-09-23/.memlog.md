## 2026-09-23 [decision] (arch) — AD-1 content source-of-truth and read path
The `sanjit-content` repo is the source of truth for static content (case studies, patterns, lab tools, currently-building snapshots, CV). The deployed site reads content via **git-clone-at-build + webhook-triggered on-demand revalidation**: the build step does a shallow `git clone` of the content repo into the Next.js build container; a GitHub Action `repository_dispatch` calls `POST /api/revalidate?tag=<tag>` on content push; the route calls `revalidateTag()` to regenerate only the affected route within 5 seconds. Prevents the divergence where one route uses git-cloned files and another reaches the GitHub API directly. Binds: FR-12, FR-13, FR-14, CAP-5.

## 2026-09-23 [decision] (arch) — AD-2 live state store split
Vercel KV is the canonical "live state" store. Two namespaces: `now` for currently-building entries (the phone-editable side), and `contact` for the contact-form queue. The content repo remains the source of truth for static content and the last-good snapshot of `/now`. Prevents the divergence where one consumer reads from KV and another reads from the content repo's `now-snapshot.json` for the same field. Binds: FR-15, FR-17, CAP-6.

## 2026-09-23 [decision] (arch) — AD-3 Vercel edge region
The deployed site runs on Vercel's default region (iad1) with **edge functions enabled for the currently-building GET and the forward-pdf POST**. The slow-network first-paint route (homepage, all SSG/ISR pages) ships from the default region. Reasoning: BD visitors see the static HTML served from Vercel's global CDN (no per-region cold start for cached pages), and the two serverless endpoints that take user input run at the edge for low-latency responses everywhere. Prevents the divergence where someone deploys the edge function in a non-edge runtime and the cold-start penalty blows the perceived latency budget. Binds: FR-6, FR-17, NFR-P.

## 2026-09-23 [decision] (arch) — AD-4 pattern citation resolution at build
Pattern citations (`patterns: ["canonical-model", ...]` in case-study frontmatter) are resolved at **build time** by string match on the pattern slug, validated against the live `patterns/` directory at build start. The case-study page renders "Patterns cited" cards linking to `/patterns/<slug>#move-<n>` — where `<n>` defaults to `move-1` unless overridden via `pattern_moves: { "canonical-model": 3 }` in the case-study frontmatter. Prevents the divergence where two case studies cite the same pattern but surface different moves of it. Binds: FR-8, FR-9, CAP-3.

## 2026-09-23 [decision] (arch) — AD-5 malformed-frontmatter error model
Malformed frontmatter fails the build. Specifically: if a `Zod.safeParse()` fails on any published entry (status === `published`), the build exits non-zero with a per-file diagnostic. `draft` entries may have malformed frontmatter and are still rendered in preview; only `published` entries must pass validation. Prevents the divergence where a content author ships a broken entry and the build silently falls back to a "missing field" render. Binds: FR-13, NFR-C.

## 2026-09-23 [decision] (arch) — AD-6 live architecture diagram
The "How this site is built" page renders an MDX-embedded React component that reads `architecture-diagrams.md` from the spec-companion folder at build time and renders the diagrams as SVG with click affordances. The diagrams live in a companion (Spec Law rule 2); the React component is a thin renderer that styles the text-art with hover states and links. When the architecture changes, the companion file changes, the content webhook fires, the page revalidates. Prevents the divergence where the deployed diagram shows boxes and arrows that don't match the actual code. Binds: CAP-7, the architecture-diagrams companion.

## 2026-09-23 [decision] (arch) — AD-7 forward-pdf generation
The PDF forward artifact is generated **server-side** via Puppeteer (`@sparticuz/chromium`) on a Vercel serverless function at `/api/forward-pdf`. The function returns a single-page A4 PDF with the spine line + four proof vectors + one recommended case study + canonical site URL. If the function times out (default 10s, configurable to 30s) or fails on Chromium cold start, the modal falls back to client-side `window.print()` with a print-only stylesheet that produces an equivalent layout. Prevents the divergence where the recruiter sees no PDF and the forward fails. Binds: FR-4, FR-6, CAP-2.

## 2026-09-23 [decision] (arch) — AD-8 deterministic recruiter-mode state
Recruiter-mode is a client-side state derived deterministically from one source: `(URL has `?for=recruiter`) OR (localStorage.for_recruiter === 'true')`. The `<RecruiterModeProvider>` reads on mount, applies the value via React context, and updates both `localStorage` and `?for=recruiter` URL param on toggle. No server hit, no behavior-derived prediction. Prevents the divergence where the same visitor sees different recruiter-mode states across pages. Binds: FR-3, CAP-1.

## 2026-09-23 [decision] (arch) — AD-9 build pipeline must not run on content edits
The main Next.js build pipeline runs only on changes to the **code repo** (`sanjit-portfolio`). Content edits to `sanjit-content` trigger only `revalidateTag()` via webhook — never a new build. Enforced via: GitHub Actions workflow separation (two repos, two pipelines, two deployment triggers), and a CI assertion that inspects the Vercel deployment log for the past 7 days and fails the audit if any deployment was triggered by a content-repo commit. Prevents the divergence where content edits trigger code builds and burn CI minutes / cold starts unnecessarily. Binds: FR-12, FR-14, CAP-5, SM-5.

## 2026-09-23 [decision] (arch) — AD-10 stale-state fallback contract
The `/now` feed and the homepage's "currently building" section call `GET /api/now`. The handler reads from Vercel KV; if KV returns no entries OR the most-recent entry is older than 7 days, the handler returns the last-good snapshot from `/content/now-snapshot.json` with `fallback: true` and `last_updated: <ISO>`. The component renders a visible `(last updated N days ago)` tag when `fallback` is true. The handler never returns an empty array without also returning `fallback: true`. Prevents the divergence where one consumer (homepage) silently shows nothing while another (`/now`) shows the snapshot. Binds: FR-15, FR-16, FR-17, CAP-6.

## 2026-09-23 [decision] (arch) — AD-11 strict CSP + no third-party JS on critical path
`next.config.js` sets a Content-Security-Policy header that: (a) bans all third-party scripts on first paint, (b) allows Plausible's domain only when loaded via `next/script strategy="lazyOnload"`, (c) allows Resend's API endpoint for the contact-form serverless POST, (d) bans inline `<script>` tags except for the Next.js runtime nonce. No chat widgets, no font CDN scripts, no analytics CDN scripts beyond Plausible. Prevents the divergence where someone adds an analytics script inline and breaks the LCP budget. Binds: FR-22, NFR-P, NFR-S.

## 2026-09-23 [decision] (arch) — AD-12 route-level invariants in CI
Three CI assertions run on every PR: (1) **spine-line invariant** — every public route's rendered HTML contains the spine-line variant in the persistent header; (2) **proof-number invariant** — every public route contains at least one of the four proof numbers in its rendered HTML; (3) **return-path invariant** — every public route contains a navigation link back to `/`. Failing any assertion fails the build. Prevents the divergence where a new route ships without the decentralized-proof treatment. Binds: FR-10, FR-11, CAP-4.

## 2026-09-23 [decision] (arch) — AD-13 no-SPA, island-only hydration
The site does NOT use a global SPA shell. Each route is a server-rendered HTML document; client components are imported only where they earn weight: `<RecruiterModeToggle>`, `<ForwardModal>`, `<PatternAnchorScroller>`, the `interactive: true` Lab tool iframe loader, and the `<PerformanceBudgetBeacon>` (deferred). Every other component is a server component. The bundle is split per-route; the homepage carries only the homepage's client components. Prevents the divergence where someone "improves" the architecture by wrapping pages in a layout-level client provider and re-introducing global hydration. Binds: FR-19, FR-20, FR-22, NFR-P.

## 2026-09-23 [decision] (arch) — AD-14 forward-modal URL contract
The forward-modal generates a deterministic URL shape: `https://sanjit.dev/?for=recruiter&forward=1&case=<slug>`. The `forward=1` query param drives the Open Graph / Twitter Card meta tag selection (sets `og:image` to the forward-artifact variant and `og:description` to the spine line + proof numbers). The URL is the canonical share form; the PDF is the fallback for corporate networks that block share-URL previews. Prevents the divergence where one share form renders the spine line and another renders the homepage hero. Binds: FR-4, FR-5, FR-11, CAP-2.

## 2026-09-23 [decision] (arch) — conventions: naming, data formats, state mutation
- **Naming.** Files: kebab-case (`wellbook.mdx`, `canonical-model.mdx`). Slugs: filename-without-extension, overridable via frontmatter `slug`. Routes: kebab-case paths (`/work/wellbook`, `/patterns/canonical-model`). Component names: PascalCase. Client components: prefix with `Client` or annotate with `"use client"` at file top. Types: PascalCase, Zod schemas end in `Schema`.
- **Data & formats.** All content frontmatter is ISO 8601 dates (`created`, `updated`, `started`). Proof-vector numbers are stored as strings ("10K+ users", "35%") to allow display-formatted copy. Error shapes from serverless functions follow `{ error: { code: string, message: string, request_id: string } }`. ISR tag names use `case-study:<slug>`, `pattern:<slug>`, `lab:<slug>`, `now`, `cv`. Open Graph / Twitter Card types are typed in `lib/meta.ts`.
- **State & cross-cutting.** Mutations on live state go through serverless functions only (never directly from the client). Errors logged via `console.error` (no PII); Sentry captures client errors only. Config via Vercel env vars; no `.env` files committed. Auth: none for v1; the contact-form serverless function uses a per-form honeypot + Cloudflare Turnstile token to block bots. Logging format: structured JSON with `request_id` correlation.

## 2026-09-23 [decision] (arch) — AD-15 shadcn/ui for interactive primitives only
Added AD-15. Scope: shadcn/ui (Radix-based primitives copied into `components/ui/`) for exactly three components: `Dialog` (ForwardModal body — focus trap, escape-to-close, scroll lock, screen-reader announcements), `Toggle` (RecruiterModeToggle — pressed-state ARIA), `Tooltip` (Patterns cited deep-link cards). Adding any new shadcn primitive requires updating AD-15; adding any hand-rolled component does not. Binds: FR-3, FR-4, FR-6, NFR-A, NFR-P.
