There is no clever trick behind this site. Static HTML, a single CSS file, one tiny JS bundle, and a fixed-position canvas that listens to scroll. The whole site ships in under 20 KB of page weight and renders on the first paint. The diagram on the right is the actual architecture — not a metaphor for one.

02 / Stack cards

What each layer
actually runs on.

Tooling tier by tier. Boring is the point — fewer moving pieces means fewer things that can break.

L1 — Network

Preloaded fonts, single RTT

The HTML drops link-preload for two Google Fonts. HTTP/2 multiplexing gets the rest. Total cold-cache to first contentful paint is typically under 600ms on a 4G connection.

Inter Space Grotesk JetBrains Mono preconnect
L2 — Pages

Hand-written static HTML

9 routes, one file each. No SPA framework, no client routing. Right-click "view source" still shows the actual content. Search works without JavaScript.

HTML5 ~14KB 9 files
L3 — Signature Canvas

Mode-adaptive SVG node graph

The top-right 240×240 SVG persists between pages with a different graph each time — dual-ring on home, decision-graph on the pattern page, timeline on about. ~250 lines of SVG markup total.

SVG CSS transitions 9 modes
L4 — Command palette

⌘K · role=dialog · 100% accessible

Vanilla-JS modal that fires on ⌘K / Ctrl-K. Trap focus inside the input and list, scrim click closes, escape closes, arrow keys move selection, fuzzy text filter. WCAG 2.1 AA verified.

aria-modal focus-trap fuzzy
L5 — Magnetic CTA

Pointer magnetism, gated properly

The hero "Get in touch →" leans toward the cursor by 0.18× the pointer offset. Disabled entirely when prefers-reduced-motion is on, and skipped when pointer:coarse (mobile).

pointermove 0.18 clamp reduced-motion
L6 — Design tokens

~30 CSS custom properties

Everything reads from --bg, --accent, --fg, --radius-md and friends. Switching palettes is one CSS file swap. The cinematic dark theme is the default; the modal command palette swaps fg colors automatically.

--bg --accent --gradient-text

04 / Decisions

What I considered,
and why I didn't.

The boring stack was a deliberate choice after trying several more ambitious ones.

D1
No SPA
Did consider Next.js / Astro. The 30ms client-side route transition wasn't worth 280KB of framework code for a portfolio that loads in two clicks.
consideredrejected
Plain HTML
D2
Inline everything
CSS and JS are inline in each page. Costs cache efficiency across routes; gains the ability to serve a single edge response with zero round-trips per route.
tradeoff
Acceptable
D3
No icon library
Phosphor/Heroicons would have worked. The load is low enough that the two arrow glyphs (→, ⌘K) earn their keep inline as Unicode codepoints.
unicode
2 glyphs
D4
No build step
Not using PostCSS, not using a bundler. CSS variables and modern selectors cover 95% of what a preprocessor would have given me. The other 5% would have cost 5MB of node_modules.
boring-on-purpose
View-source
D5
Single SVG canvas
The signature canvas is the only persistent visual element across all 9 pages. It morphs per page (dual-ring, decision-graph, timeline, etc.) but it's one DOM element the browser already knows about.
SVG
